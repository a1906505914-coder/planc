每行一个行项目，`col29` 本币金额**带符号**（正=借、负=贷）。

## 2. 期间三口径（最重要的坑——分月对不上 TB 的根因）

同一个凭证有 **3 个日期/期间**，口径不同：

| 口径 | 数据来源 | 用途 |
|---|---|---|
| **记账期间** | col10 | GL 文件收纳（1010-3月.xlsx=期间03） |
| **过账日期** | col31 | **TB「借方1-7」列的收纳口径** |
| **凭证日期** | col28 | 仅反映凭证开具日，**≠过账日期** |

**核心规则**：GL 与 TB 勾对时，按 **过账日期（col31）∈ 年度 1-7 月 且 凭证日期（col28）≤ 年度 8月1日** 过滤。

**最终口径（2026-08-26 三层演进）**：
1. 原：凭证日期（col28）∈ 2026-01~07 → 误剔「凭证日期=2025年末、过账日期=2026」的冲销凭证（利息支出 3 月差 300 万）
2. 改：过账日期（col31）∈ 1-7 → 引入「凭证日期=8月初、过账日期倒填7月底」的 8/5 凭证（税金及附加 6403 差 100,325、所得税 6801 差 4,168,801）
3. **终版：过账日期 ∈ 1-7 且 凭证日期 ≤ 8月1日** → 全部利润表科目归零（收入/成本/税金/所得税/利息收支全部 0 差异）

**8月1日上限由来（TB 导出时点反推）**：
- VERBR（CO 成本消耗结转）凭证日期 **8/1**、过账 7/31 → TB **含**（8/1 已过账）
- 计提税凭证（6500004126/4132/4134 城建税教育费附加、6500004135 所得税）凭证日期 **8/4-8/5**、过账 7/30-31 → TB **不含**（TB 导出时点约 8/1-8/3，尚未过账）

**bug 历史**（2026-08-26 修复）：
- 原 `read_gl_rows`（sap_adapter.py）用 **col28 凭证日期**过滤 → 把「凭证日期=2025年末、过账日期=2026」的冲销凭证**误过滤**，TB 却含（按过账日期）→ 分月明细 vs TB 对不上。
- 实例：`6500001378 冲审计调整长期借款重分类`（凭证日期 2025-12-31、过账日期 2026-03-21，贷 660302 **-3,000,922.22**）→ 利息支出 3 月差 300.09 万；`6200000266 驻马店四季度资金池冲销行`（凭证日期 2025-12-23、过账日期 2026-01-08，贷 **-90,138.31**）→ 1 月差 9.01 万。
- 修复：过滤 `_dt31 = _excel_date(r.get(31))`，年份用 `str(yy)` 代替硬编码 '2026'；`_GL_CACHE_COLS` 加 col31。
- 第二层：过账日期过滤引入 8/5 凭证 → 增加「凭证日期 ≤ 8月1日」条件（_dt28 校验）。

**审计调整/冲销凭证特征**：凭证日期落在上年末（2025-12-xx），过账日期在本年（2026-0x），摘要含「冲审计调整」「冲回」「重分类」。

## 3. 缓存机制（不要踩）

- `sap_common.load_comp_gl_disk`：读 GL 文件 → `.gl_cache/{comp}_v1_{hash}.pklz`（gzip pickle）。
- **缓存 key 基于 cols 集合**：改列集（如加 col31）→ 新 key，自动重建，**不覆盖旧缓存**（旧进程/旧调用不受影响）。
- `_GL_CACHE_COLS`（sap_common.py:641）= {0,1,5,6,10,11,12,17,19,21,24,25,26,27,28,29,31}。
- 进程级缓存：`read_gl`/`read_gl_rows` 用 `_CACHE_GL`（key=(comp 或 exclude_co+主体集合)），构造一次后续命中。
- 新增/改列后首次调用会全扫重建（1010 约 90 秒），88 主体批量重建约 1-2 小时。

## 4. TB（科目余额表）读取坑

文件：`数据/{年度}/科目余额表/{主体}.xlsx`（SAP FS10N 导出，按**科目×利润中心×期间**拆分行）。

- 表头：col2=科目名、col6=利润中心、col8=期间（"三月 2026 2026.003"）、col9=余额结转、col12=借方1-7、col13=贷方1-7。
- `read_km`（sap_adapter.py:164）：`jf/df` 来自 TB 借方1-7/贷方1-7，**每行=当月发生额**（非累计），加总=1-7 月合计。

### ⚠️ 父级重复计数坑（2026-08-26 教训）
TB 一级科目（如 6600）的 `jf` **= 全部子目合计**。若 `startswith('6600')` 全累加 → **父级+子级 = 双倍**（6600 借发 5.31 亿 ×2 = 10.63 亿）。
**统计必须只取叶子子目**（无其他科目以它为前缀），或用一级科目值。

## 5. 外币评估镜像（虚增发生额的主因）

- 外币期末重估凭证：每笔「借 660303 汇兑损失 / 贷 660304 汇兑收益」几乎对冲。
- 实例（1010）：660303 GL 借方 **7.79 亿** + 贷方 **7.35 亿** = 净借 4,389 万；TB 只反映**净额**（借发 1,192 万）。量级差 65 倍，**不是数据缺失**，是 TB 已净额化。
- 识别：摘要含「评估」「上评估」（期初评估冲销）；同凭证借贷镜像。
- 处理：费用底稿 P 列用净额（借-贷），差异列暴露镜像金额供审计查因；凭证抽查按 >PM 必抽层全量覆盖。

## 6. CO 结转（净额 0 的虚增）

- 期间=07、过账日期 8/5 的凭证（CO 成本结转/分摊），借贷对冲**净额=0**，TB（按过账日期 1-7）不含。
- 实例：7 月文件 23,713 行「期间=07 过账日期=2026-08」，净额 ≈ 0。
- read_gl 按过账日期过滤自动剔除（与 TB 一致）。`exclude_co=True`（read_gl_rows）可额外剔除 is_co=1 行。

## 7. 费用科目分类（SAP 与 U8 不同）

- SAP TB 只有 **6600 费用总池**（含管理/销售/制造/研发全部明细），**无 FR 拆分**。
- 费用类别**只能从 GL 功能范围列（col19）拆分**：6601销售/6602管理/5101制造/5301研发；660006 研究开发费不论 FR 一律研发；6603 财务费用按编码定性。
- 对应代码：`expense_detail._sap_fee_cat`。
- 制造费用（5101）贷方=结转生产成本（真实内部流转），**保持借方 gross 不抵消**；其他费用存净额（借-贷）。
- ⚡ 研发费用二级细分（2026-08-26）：SAP 研发科目全在 **660006** 前缀（66000601xx 人员人工/直接投入/...），
  c6 截断会全合并成 '660006' → 二级 key 改用**完整科目码**（read_all_tb/read_all_gl 对 660006 不截断；
  build_expense_spec_rows 放行 660006 前缀）。

## 9. 残留差异（全部原因已查明）

1. **主营成本 6401 差 9,181.41** = `6500004117 转出阿曼1013-SCKF-25118税`（借 6401 / 贷进项转出，凭证日期/过账日期都 2026-07-31、期间 07）。日期全正常但 TB 不含 → **TB 导出时点特例**（实际过账晚于 TB 导出），read_gl 无法用日期规则排除，属 TB 与 GL 的时点差异。
2. **财务费用整体差 572 万** = 汇兑损失 13,794,515 + 汇兑收益 -8,073,697 + 手续费 -873：
   - **汇兑损失**：GL 借 **8.67 亿** / 贷 **8.42 亿**（对冲 **97%**），净 2,571 万 vs TB 1,192 万 → 外币评估镜像，TB 对评估净额化处理不同，非 bug
   - **汇兑收益**：GL 借 3.92 亿 / 贷 4.00 亿，净 -822 万 vs TB -14 万 → 同因
   - **手续费**：GL 净 1,373,081 vs TB 1,373,953，差 -872（四舍五入/边角）
3. 研发费用：**8 个研究开发费子科目已全部勾平（R=0）**；仅剩「工资附加费-职工教育经费（GL补充）」3,168.32 = GL fr=5301 归类研发、TB 无对应研发二级（分类口径）
4. 二级科目分类差异（费用模块）：GL fr 拆分 vs TB 二级科目体系，正负相抵，需审计判断分类合理性。
5. **6600 期间费用总池差 2,064.94 万**（2026-08-26 已定位，全部集中在 7 月）：
   - `6500004127 计提工资` 2,000 万（借 6600010000 / 贷 2211101011，凭证日期/过账日期/期间全为 2026-07-31）→ TB 导出时点（约 8 月初）未含
   - `66001800 安全投入` 649,432.50 → 同因
   - 1-6 月逐月 GL=TB 完全一致（66000100 工资单科目验证），GL 完整；差异=TB 导出时点缺失，需向财务核实 TB 补导
   - **口径确认**：SAP TB 的"借方1-7"实际是**净额化**（6600 一级 jf 5.31 亿、df 702 万、净额 5.24 亿）；与 GL 可比的是**净额（debit-credit）**，不是 gross 借发
6. **费用 4 类 Q-TB 假勾平已修复**（2026-08-26）：SAP 管理/销售/制造/研发 TB 无 FR 拆分，原 read_all_gl 补填 tb_l2_control（类别码 key）导致 Q 列读到 GL 自己、差异恒 0。
   现分月明细 Q/R 列留空 + 表底说明；新增「6600期间费用类别拆分核对」表做**一级总池净额勾稽**（4 类 GL 拆分 vs TB 6600 一级净额，差异 2,064.94 万已精确暴露）。

## 10. 一句话总结

**读 SAP GL 就记住三点**：① 期间口径全用**过账日期 col31**（不是凭证日期 col28、也不是记账期间 col10）；② TB 一级科目统计**只取叶子**防双倍；③ 外币评估/CO 结转是虚增主源，**净额口径核对**、镜像金额暴露不隐藏。
